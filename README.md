# Family Hub — семейный органайзер

Family Hub — мобильное PWA для совместных задач, покупок, семейных событий, заметок и обсуждений. Интерфейс выполнен в матовой чёрно-слоновой палитре, использует адаптивную нижнюю навигацию, SVG-иконки и учитывает `prefers-reduced-motion`.

**Технологии:** Vite, JavaScript ES modules, CSS, Supabase Auth, PostgreSQL, Row Level Security (RLS), SQL RPC и Supabase Realtime. Проект можно публиковать на GitHub Pages без отдельного frontend-сервера.

## Возможности

- Регистрация и вход по email/паролю через Supabase Auth.
- Создание семейного пространства, одноразовые приглашения, роли владельца/участника и удаление участника владельцем с автоматическим снятием его назначений.
- Задачи с названием, описанием, категорией, сроком, приоритетом, статусом, назначением, избранным, поиском и фильтрами.
- Восемь начальных категорий и пользовательские категории с настройкой порядка владельцем.
- Серверная фиксация выполнения задач и истории повторных выполнений; ежедневные, еженедельные, ежемесячные повторы и повторы по выбранным дням недели.
- Общий список покупок с количеством, единицами, категорией, ценой, магазином, автором, отметкой о покупке, архивом, закреплением, повторным добавлением и копированием списка.
- Обсуждения задач, покупок и событий: ответы, редактирование/удаление собственных комментариев и реакции.
- Семейный календарь, повторяющиеся события, история действий и внутренние уведомления.
- Семейные заметки, шаблоны задач, глобальный поиск по семейным объектам, настройки типов уведомлений, статистика выполнения и достижения, вычисляемые по реальной истории задач.
- JSON/CSV-экспорт журнала действий.
- PWA-оболочка, статический кэш, offline-экран и защита от кэширования семейных данных.

## Важно перед использованием

Для регистрации, общих аккаунтов, семейных данных и синхронизации необходим настоящий проект Supabase. Без настроенного Supabase приложение показывает экран настройки и не создаёт фиктивные данные.

Офлайн-режим не синхронизирует изменения с сервером. Family Hub не записывает неподтверждённые сервером операции в очередь: если интернет пропал, приложение показывает предупреждение, а операция считается сохранённой только после ответа Supabase. Семейные данные намеренно не хранятся в общем кэше браузера.

## Требования

- Node.js 22 или новее и npm (для локальной разработки/сборки).
- Аккаунт GitHub.
- Проект Supabase.
- Интернет при установке зависимостей, работе с Supabase и публикации.

## Локальный запуск

1. Распакуйте архив и откройте папку `family-hub` в терминале или в веб-среде разработки.
2. Установите зависимости:

   ```bash
   npm install
   ```

3. Скопируйте `.env.example` в `.env`.
4. Заполните только публичные frontend-параметры:

   ```dotenv
   VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
   ```

5. Настройте Supabase по следующему разделу и выполните SQL-файлы в указанном порядке.
6. Запустите разработческий сервер:

   ```bash
   npm run dev
   ```

7. Для production-сборки и локального просмотра:

   ```bash
   npm test
   npm run build
   npm run preview
   ```

## Настройка Supabase с нуля

1. Откройте [supabase.com](https://supabase.com/) и создайте проект. Сохраните пароль базы в безопасном месте — он не нужен в frontend-коде.
2. В Project Settings → API скопируйте Project URL и **публичный anon/publishable key**.
3. В Authentication → URL Configuration укажите Site URL. Для репозитория `family-hub` это будет `https://ВАШ-USERNAME.github.io/family-hub/`. Добавьте этот адрес в Redirect URLs и `http://localhost:5173/**` для локальной разработки.
4. Откройте SQL Editor и выполните файлы **строго в таком порядке**:
   - `supabase/schema.sql`
   - `supabase/migrations/202610280002_family_features.sql`
   - `supabase/migrations/202610280003_final_hardening.sql`

   `202610280001_foundation.sql` — исторический снимок первой части, повторно его выполнять не нужно.
5. Проверьте результат каждого запуска SQL Editor: миграции должны завершиться без ошибок. Если SQL Editor сообщает об ошибке, не публикуйте приложение до устранения ошибки.
6. В Authentication → Providers убедитесь, что Email включён. При включённом подтверждении email пользователь должен подтвердить адрес перед входом.
7. В Database/Replication убедитесь, что включена публикация `supabase_realtime`. Миграции пытаются добавить нужные таблицы автоматически; при ограничениях прав проверьте публикацию в панели Supabase.
8. Запустите приложение, создайте аккаунт, создайте семейное пространство и сгенерируйте приглашение. Для второго устройства создайте отдельный аккаунт, затем используйте код приглашения.

### Ключи и безопасность

- Значения с префиксом `VITE_` включаются в клиентский JavaScript и доступны посетителям сайта. URL проекта и публичный anon/publishable key предназначены для клиентского приложения.
- **Никогда не используйте `service_role` key в `.env`, GitHub Actions Variables, коде браузера или собранной папке `dist`.** Он обходит RLS.
- Доступ к семейным строкам ограничивается RLS и активным членством. Авторы, время создания, отметки выполнения/покупки и записи аудита защищены серверными триггерами/RPC.
- Публичный репозиторий должен содержать только `.env.example`, а не реальный `.env`. `.gitignore` исключает `.env*` (кроме `.env.example`), `node_modules`, `dist` и временные файлы.
- Перед использованием с важными данными сделайте тестовую семью и проверьте RLS в своём проекте Supabase. Ни одна статическая проверка без ваших учётных данных не заменяет интеграционный тест на реальном backend.

## Публикация на GitHub Pages с телефона

1. На iPhone откройте GitHub в Safari или приложении GitHub и создайте **публичный или приватный** репозиторий с точным именем `family-hub`.
2. Распакуйте `family-hub.zip` в приложении «Файлы» или в файловом менеджере, который умеет извлекать ZIP.
3. **Предпочтительный вариант:** откройте ZIP и загрузите содержимое папки `family-hub` в корень репозитория через **Add file → Upload files**, сохранив структуру папок. В корне должны находиться `index.html`, `package.json`, `src/`, `public/`, `supabase/` и `.github/`.
4. Если iPhone не позволяет загрузить папки с сохранением структуры, используйте ZIP-режим: создайте в репозитории файл `.github/workflows/deploy.yml` через **Add file → Create new file**, вставьте приведённый ниже bootstrap-workflow и сохраните commit. Затем загрузите сам `family-hub.zip` в корень репозитория. Workflow распакует архив в рабочей среде Actions перед сборкой.

   ```yaml
   name: Build and deploy Family Hub
   on:
     push:
       branches: [main]
     workflow_dispatch:
   permissions:
     contents: read
     pages: write
     id-token: write
   concurrency:
     group: pages
     cancel-in-progress: true
   jobs:
     build:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - name: Unpack uploaded ZIP
           run: |
             if [ -f family-hub.zip ] && [ ! -f package.json ]; then
               mkdir -p /tmp/family-hub-unpack
               unzip -q family-hub.zip -d /tmp/family-hub-unpack
               cp -R /tmp/family-hub-unpack/family-hub/. .
             fi
         - uses: actions/setup-node@v4
           with:
             node-version: 22
         - run: npm install --no-audit --no-fund
         - run: npm run build
           env:
             VITE_SUPABASE_URL: ${{ vars.VITE_SUPABASE_URL }}
             VITE_SUPABASE_ANON_KEY: ${{ vars.VITE_SUPABASE_ANON_KEY }}
         - uses: actions/configure-pages@v5
         - uses: actions/upload-pages-artifact@v3
           with:
             path: dist
     deploy:
       environment:
         name: github-pages
         url: ${{ steps.deployment.outputs.page_url }}
       runs-on: ubuntu-latest
       needs: build
       steps:
         - uses: actions/deploy-pages@v4
           id: deployment
   ```

5. Внизу страницы загрузки добавьте commit в ветку `main`.
6. Откройте Settings → Secrets and variables → Actions → Variables → New repository variable. Создайте две переменные:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`

   Это публичные frontend-параметры, не секретные ключи сервера.
7. Перейдите в Settings → Pages и выберите **GitHub Actions** как источник публикации.
8. Откройте вкладку Actions. Дождитесь завершения workflow **Build and deploy Family Hub**. Если он завершился ошибкой, откройте шаг Build и изучите лог.
9. После успешного workflow сайт будет доступен по адресу `https://ВАШ-USERNAME.github.io/family-hub/`. Имя пользователя GitHub чувствительно к точному написанию.
10. Убедитесь, что в Supabase Auth Site URL/Redirect URLs совпадают с опубликованным адресом.
11. Для установки на iPhone откройте опубликованный сайт в Safari → «Поделиться» → «На экран Домой». На Android откройте сайт в поддерживаемом браузере и выберите «Установить приложение»/«Добавить на главный экран».

### Как обновить приложение

Измените файлы в репозитории и создайте commit в `main`. GitHub Actions повторно установит зависимости, соберёт `dist` и опубликует обновление. Service Worker использует сетевую загрузку статических ресурсов с кэшированным резервом офлайн и удаляет старые кэши Family Hub при активации новой версии. Если приложение долго показывает старую версию, полностью закройте установленное PWA и откройте его снова после подключения к интернету.

## Тесты и проверка

```bash
npm test
```

Тесты проверяют валидацию полей, email/пароль, приветствие, расчёт повторений, ориентировочную стоимость покупок и ключевые контракты SQL-миграций. Синтаксис JavaScript можно проверить так:

```bash
find src -name '*.js' -print0 | xargs -0 -n1 node --check
node --check vite.config.js
node --check tests-validation.test.js
```

### Что проверено в этой сборочной среде

- `node --test`: 11 тестов пройдены в финальной проверке.
- `node --check` выполняется для исходных JS-файлов.
- Проверены наличие основных файлов и статические контракты SQL.
- Попытка `npm install --no-audit --no-fund` завершилась по тайм-ауту в этой среде, поэтому здесь пока нельзя подтвердить production-сборку Vite или тест браузерного интерфейса.
- SQL миграции не исполнялись в реальном Supabase-проекте. Сквозные сценарии регистрации, приглашения второго участника, двух устройств и изоляции двух семей требуют настройки проекта и ручной проверки.

## Типичные ошибки

- **«Подключите Supabase»** — проверьте URL и публичный ключ, затем пересоберите сайт.
- **Ошибка регистрации/входа** — проверьте Email Provider, пароль, подтверждение email и URL Configuration.
- **Ошибка SQL/RLS** — убедитесь, что выполнены `schema.sql`, `202610280002_family_features.sql`, затем `202610280003_final_hardening.sql`; читайте сообщение SQL Editor и исправьте первую ошибку.
- **Второе устройство не видит изменения** — проверьте подключение к интернету, членство второго пользователя, Realtime publication и вкладку Console/Network.
- **GitHub Pages показывает 404 или пустую страницу** — имя репозитория должно быть `family-hub`, workflow должен завершиться успешно, а Pages должен использовать GitHub Actions.
- **Сайт не обновился на iPhone** — закройте PWA, откройте его снова онлайн; при необходимости удалите ярлык с экрана «Домой» и добавьте заново после проверки обновлённого сайта в Safari.
- **Не удаётся установить зависимости** — проверьте соединение и версию Node.js (22+), затем повторите `npm install`.

## Бесплатные тарифы и ограничения

GitHub Pages и Supabase могут использоваться в рамках бесплатных тарифов при соблюдении актуальных условий провайдеров. Лимиты базы, трафика, Realtime, количества пользователей и правила приостановки проектов зависят от текущих тарифов и могут меняться; проверьте их на официальных страницах GitHub и Supabase. Бесплатный тариф не означает неограниченное хранение, гарантированную доступность или бесплатные SMS/email-рассылки.

## Известные ограничения этой версии

- Уведомления о новых задачах, изменениях статуса, покупках, событиях и комментариях сохраняются в центре уведомлений. Отдельный планировщик серверных напоминаний о приближающихся сроках (например, через Supabase Cron/Edge Functions) не включён.
- Офлайн-кэш содержит только оболочку и статические ресурсы. Очереди несинхронизированных операций нет; серверные изменения требуют сети и подтверждения Supabase.
- Переключатели День/Неделя/Месяц календаря фильтруют список событий по периоду; это не полноценная сетка календаря.
- Восстановление пароля по email не реализовано. Для восстановления используйте административные возможности Supabase Auth.
- Проверки не включают живой сценарий с двумя аккаунтами/семьями, потому что в среде сборки нет настроенного проекта Supabase.
